# learn-gis — 产品计划（Plan）

> 状态：v1.0 · 决策已确认（见 §7）
> 一句话：一个"以问答驱动、从 0 学任何技能"的学习应用，第一个技能包是 GIS（地理信息系统）。

---

## 1. 目标与非目标

### 目标
1. 用**问答（刷题 + 讲解释疑）**作为学习主循环，而不是读长文档。
2. **技能可插拔**：GIS 是第一个 skill pack，后续加 HTTP、SQL、算法等只需加内容包，不改引擎。
3. 部署在 Vercel，纯预览级体验：秒开、移动端可用、离线可继续（本地进度）。
4. 依赖版本全部锁定，可复现构建。

### 非目标（v1 不做）
- 不做多用户账号体系、排行榜、社交。
- 不做视频课程、直播。
- 不做后台 CMS（内容以仓库内 JSON/MDX 为准，靠 PR 维护）。
- 不做 GIS 数据托管/后端空间数据库（PostGIS 只作为**学习内容**，不是运行时依赖）。

---

## 2. 产品形态（需要你拍板）

### 形态 A：题库驱动（推荐 v1）
本地题库 → 出题 → 答题 → 即时判卷 + 解释 → 错题进入复习队列（间隔重复）。
优点：零 API 成本、可离线、结果可测、内容可版本化。
缺点：题目需要人工/半自动生产。

### 形态 B：AI 问答（v2 可选增强）
用户提问/被追问，由 LLM 出题与判卷（含开放式答案）。
优点：灵活、可自适应难度。
缺点：成本、延迟、答案不稳定、需配 key 与速率限制。

**建议**：v1 用形态 A 打底；把 `QuestionSource` 抽象出来，v2 加一个 `LlmQuestionSource` 即可，不动 UI。

## 3. 学习闭环设计

```
技能地图 → 模块 → 讲义（短，MDX） → 测验（5~10 题）
        → 结果页（错题解释 + 相关链接）
        → 复习队列（SM-2 简化版，今日到期题）
```

关键体验点：
- 一题一屏，键盘可完成（1-4 选项、Enter 下一题）。
- 答错立刻给**为什么错**（干扰项级解释，不只是正确答案）。
- 每模块结束给"掌握度"（%），低于阈值提示重练。
- 地图类题目可交互（Leaflet/MapLibre 内嵌），非纯文字。

## 4. 里程碑

| 阶段 | 交付物 | 验收 |
|---|---|---|
| M0 脚手架 | Next.js App Router + TS strict + Tailwind，版本锁定、CI、Vercel 空站上线 | `npm ci && npm run build` 通过；预览 URL 可访问 |
| M1 引擎 | 内容 schema（Zod 校验）+ 10 道 demo 题 + 答题状态机 + 结果页 | 单模块可完整答题，判卷正确率 100%（单测覆盖 reducer） |

| M3 复习 | 进度持久化 + SM-2 复习队列 + 今日复习页 | 关页面重开进度不丢；到期题正确进入队列 |

## 5. 技术选型（已对齐 ../ink_template）

沿用 ink_template：Next.js 16.3.2（App Router，`app/` 在根目录）+ React 19.2.8 + TS strict + Tailwind 3.4（CSS 变量设计令牌）+ Radix/cva/lucide + next-themes + `@vercel/analytics` + Neon + Drizzle + Vitest/Playwright。
新增：Zod（内容校验）、MDX 或结构化讲义（二选一）、Leaflet/MapLibre（仅地图路由动态加载）。
锁版：next/react/react-dom 精确版本 + 提交 `package-lock.json` + `npm ci`，另补 `.nvmrc`(22) 与 `engines`。详见 `docs/SPEC.md` §6、§9。

## 6. 风险

1. **内容准确性**：GIS 概念（投影、EPSG、瓦片）容易讲错 → 每题带 `refs` 权威链接，你需 review 一轮。
2. **交互地图拖累性能**：地图库体积大 → 动态 import + 只在地图题/示例中加载。
3. **题库生产成本**：先做 10 题验证闭环，再批量生产，避免写了 100 题发现 schema 不对。
4. **版本漂移**：Next/React 更新快 → 精确版本 + lockfile + engines + CI 用 `npm ci`。
