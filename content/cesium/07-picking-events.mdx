## 1. ScreenSpaceEventHandler：两段式事件模型

浏览器的 mouse/click 事件只给你**屏幕像素坐标**；三维场景里同一个像素对应一条射线，打中的可能是球面、楼、实体或"什么都没有"。Cesium 的事件封装负责第一段，**pick** 负责第二段：

```js
const handler = new Cesium.ScreenSpaceEventHandler(viewer.scene.canvas);

handler.setInputAction((movement) => {
  // movement.position：屏幕像素坐标 { x, y }
  const picked = viewer.scene.pick(movement.position);
  if (Cesium.defined(picked) && picked.id) {
    // 打中了 Entity：picked.id 就是那个实体
    console.log("点中了实体：", picked.id.name);
  } else {
    console.log("点中了空地");
  }
}, Cesium.ScreenSpaceEventType.LEFT_CLICK);

// 离开页面时解绑，防止内存泄漏
// handler.destroy();
```

常用事件类型（`ScreenSpaceEventType`）：`LEFT_CLICK` / `DOUBLE_CLICK` / `RIGHT_CLICK` / `MOUSE_MOVE` / `LEFT_DOWN` / `LEFT_UP` / `WHEEL`。`MOUSE_MOVE` 的回调参数是 `{ endPosition, startPosition }`（移动轨迹的起止像素）；而 `LEFT_CLICK` 自带 **5 像素**位移容差（源码 `_clickPixelTolerance = 5`）——按下与抬起之间移动超过 5px 就不算点击。这正是"拖转地球不会误触点击"的原因，做「点击 vs 拖拽」区分时可以直接依赖这个行为。

<Callout type="must" title="必背 · 拾取三条">
1. 事件挂在 `viewer.scene.canvas` 上，回调拿屏幕坐标
2. `Cesium.defined(picked)` 判空是第一步——大多数像素点打不中任何东西
3. `picked.id` 是 Entity；没有 `.id` 的（3D Tiles 要素/地形）走 `picked.primitive` 分支
</Callout>

## 2. pick 与 drillPick：打中一层还是打穿多层

`scene.pick` 返回**最上层**的一个对象；`scene.drillPick(position)` 返回该像素上**从上到下的整列**对象：

```js
// 透明多边形叠着点实体——一次 click 两个都想要
const hits = viewer.scene.drillPick(movement.position);
for (const hit of hits) {
  if (hit.id) console.log("实体：", hit.id.id);
}
```

经验：交互选择器（点选一个目标）用 `pick`；"这一片都有什么"（属性穿透、叠层分析）用 `drillPick`。后者每个像素做多次射线求交，成本更高，不要放进 MOUSE_MOVE。

## 3. Entity 拾取与 3D Tiles 要素拾取

两类拾取结果的取值路径不同，先分型再取值：

```js
handler.setInputAction((movement) => {
  const picked = viewer.scene.pick(movement.position);
  if (!Cesium.defined(picked)) return;

  if (picked.id) {
    // ── Entity 路径（第 04 章） ──
    const e = picked.id;
    console.log(e.name, e.properties?.getValue?.());
  } else if (picked.primitive instanceof Cesium.Cesium3DTileset) {
    // ── 3D Tiles 要素路径（第 06 章） ──
    // 批表属性挂在要素上（新版 API：picked.getContent? 视版本而定）
    console.log("3D Tiles 要素", picked);
  }
}, Cesium.ScreenSpaceEventType.LEFT_CLICK);
```

3D Tiles 要素的属性读取随版本演进（`picked.getPropertyIds/getProperty` 或 content 接口），用到时以你锁定的 Cesium 版本文档为准——这也是课程一直强调"API 以版本为准"的原因。

## 4. 经典交互：悬停高亮 + 点击弹窗

把本章组件拼成一个完整交互——悬停变亮、点击打日志：

```js
let lastPicked = null;
let lastColor = null;

handler.setInputAction((movement) => {
  const picked = viewer.scene.pick(movement.endPosition);
  // ① 先把上一个恢复原色
  if (Cesium.defined(lastPicked)) {
    lastPicked.point.color = lastColor;
    lastPicked = null;
  }
  // ② 打中新实体则高亮
  if (Cesium.defined(picked) && picked.id?.point) {
    lastPicked = picked.id;
    lastColor = lastPicked.point.color.getValue();
    lastPicked.point.color = Cesium.Color.YELLOW;
    viewer.container.style.cursor = "pointer";
  } else {
    viewer.container.style.cursor = "default";
  }
}, Cesium.ScreenSpaceEventType.MOUSE_MOVE);
```

模式总结：**恢复旧状态 → 判定新状态 → 改光标**。所有 hover 类交互都是这个三步骨架，弹窗只是把 `console.log` 换成你自己的 UI 组件（把 `picked.id.properties` 传给它即可）。

## 5. 本章小结

- 两段式：浏览器事件给屏幕坐标，`scene.pick` 给三维对象——分工清晰。
- `defined` 判空是第一行；Entity 看 `picked.id`，3D Tiles 要素走 primitive 分支。
- `pick` 取最上层，`drillPick` 打穿整列——按交互语义选，别在 MOUSE_MOVE 里滥用。
- 悬停高亮三步骨架：恢复旧状态 → 判定新状态 → 改光标。
