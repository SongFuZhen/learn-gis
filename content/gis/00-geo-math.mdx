## 一句话

地图上的每一个点，都是一组数字——**先搞清这组数字在什么坐标里、用什么单位**，再谈 GIS，否则后面的投影、EPSG、缓冲距离全是空中楼阁。

## 1. 笛卡尔坐标：GIS 的"平地"

笛卡尔平面直角坐标由三件事确定：一个**原点**、两条**互相垂直的数轴**、以及每条轴的**单位与正方向**。点是 `(x, y)`，空间里再加一个 `z`。

GIS 里同时存在三种"平面"，方向约定完全不同：

| 场景 | x 轴 | y 轴 | 象限 |
|---|---|---|---|
| 数学 / 解析几何 | 向右 | 向上 | 逆时针 I → IV |
| 屏幕 / Canvas / 图像 | 向右 | **向下** | 顺时针 |
| 中国测量坐标（高斯成果表） | **向北** | **向东** | 顺时针（北西 = I） |

所以看到 `x=4350000, y=38500000` 这种 7~8 位数，先别当经纬度——那是高斯-克吕格平面坐标（米），x 是北坐标、y 是东坐标（含 3° 或 6° 带号前缀）。

> EPSG 的 `axis order` 属于坐标系定义的一部分：`EPSG:4326` 的 WKT 轴序是 `lat, lon`，而 GeoJSON、大多数前端库、数据库里存的是 `lon, lat`。**顺序搞反是最常见的一类 bug**，两条坐标各自的合法范围（±90 vs ±180）能让它静默通过一部分校验。

## 2. 角度：度、分、秒

一个圆周 360°，1° = 60′，1′ = 60″。传统大地测量成果用度分秒（DMS）书写，程序里一律换成**十进制度**（decimal degrees）再计算：

```
40°26′46″ = 40 + 26/60 + 46/3600 = 40.446111°
```

反方向：`0.446111° × 60 = 26.7667′`，取整得 26′，余 `0.7667′ × 60 ≈ 46″`。

DMS 是"书写格式"，不是"另一种单位"——它和十进制度之间是换算关系，而**角度与弧度才是两种单位**。

## 3. 弧度：三角函数的语言

弧度用弧长定义：圆心角 θ 对应的弧长 `s` 与半径 `r` 之比 `θ = s / r`。整圈弧长 `2πr`，所以

```
2π rad = 360°      1 rad = 180/π ≈ 57.29578°      1° = π/180 ≈ 0.0174533 rad
```

为什么 GIS 里到处是弧度：`sin / cos / tan / atan2` 的参数与返回值都是弧度。投影公式也一样，例如 Web 墨卡托的

```
y = R · ln( tan( π/4 + φ/2 ) )
```

里面的 `φ` 必须是弧度。把 30（度）直接代进去等于用 30 rad ≈ 1719° 去算，结果毫无意义。

JavaScript 里正确的写法：

```js
const y = R * Math.log(Math.tan(Math.PI / 4 + (lat * Math.PI / 180) / 2));
```

## 4. 经纬度：用角度写出的球面坐标

- **纬度 φ**：某点与赤道面的夹角，`-90°`（南极）到 `+90°`（北极）。
- **经度 λ**：某点所在子午面与本初子午面的夹角，`-180°` 到 `+180°`（或 `0°` 到 `360°`）。东经为正、西经为负是通行约定。

经纬度是**球面（严格说是椭球面）上的角度坐标**，不是米。它们不能被当成平面直角坐标直接做勾股、缓冲、面积计算。

## 5. 一度究竟有多长

纬线（东西方向）随纬度收缩，经线（南北方向）几乎不变：

| 方向 | 每 1° 的长度 | 说明 |
|---|---|---|
| 纬度（南北） | 约 110.57 km（赤道）→ 111.69 km（两极） | 椭球曲率半径变化，工程上常取 111 km |
| 经度（东西） | 约 111.32 km × cos φ | φ=60° 时只剩约 55.7 km；到极点收缩为 0 |

所以"北京到上海差 10 个经度"这种话，必须带上纬度才有长度意义。

## 6. 距离与方位：什么时候能勾股

- **小范围、已投影**（如某城市 UTM/高斯平面）：`√(Δx² + Δy²)` 足够，误差来自投影变形。
- **大范围或直接用经纬度**：用球面大圆距离（haversine）：

```
a = sin²(Δφ/2) + cosφ₁·cosφ₂·sin²(Δλ/2)
d = 2R·asin(√a)          R = 6371 km
```

- **Web 墨卡托（EPSG:3857）上量距离**：只在高纬附近失真，因为经线方向放大率是 `1/cos φ`。在 60° 纬度，图上量出的距离比实际大 2 倍。

方位角（bearing）从**正北**起、顺时针 0°~360°；而 `atan2(Δy, Δx)` 从 **x 轴（东）** 起、逆时针。两者差 90°，换算：

```
bearing = ( 90 − atan2(Δy, Δx) · 180/π + 360 ) mod 360
```

## 7. 一个常踩的坑合集

1. **度 / 弧度混用**：`Math.sin(45)` 不是 0.707（那是 45 rad），应为 `Math.sin(Math.PI / 4)`。
2. **经纬度顺序**：`[lat, lon]` 与 `[lon, lat]` 混用；`EPSG:4326` 的轴序、GeoJSON 的坐标顺序、Leaflet 的 `latLng` 恰好不统一。
3. **把经纬度当平面坐标**：在地理坐标系上直接算面积/缓冲，结果单位是"平方度"。
4. **在 Web 墨卡托上量距离/面积**：高纬会被放大，格陵兰看起来和非洲一样大。
