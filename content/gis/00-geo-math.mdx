## 本章你会学到

地图上的每一个点，说到底都是一组数字。这一章解决最基础的问题：**这组数字是什么意思、在什么坐标系里、用什么单位**。搞懂它，后面的投影、EPSG（/ˌiː piː ˈɛs dʒiː/，「伊-皮-艾斯-吉」）、缓冲分析才不是空中楼阁。

不需要任何 GIS（/ˌdʒiː aɪ ˈɛs/，「吉-艾-艾斯」）基础，只需要一点初中数学。

## 1. 先建立一个直觉：点 = 数字

打开手机地图，你的位置其实是一个**经纬度**，比如 `(116.4074, 39.9042)` 是北京天安门。在测绘图纸上，你可能看到 `(4350000, 38500000)` 这样的大数。在网页瓦片上，又是 `(x=843, y=388, z=10)` 这样的整数。

<Callout type="example" title="同一个点，三副面孔">
天安门广场中心点：

- 经纬度：`116.4074°E, 39.9042°N`（角度）
- Web 墨卡托（Mercator，/mərˈkeɪtər/，「默-凯-托」）平面：约 `(12958173, 4852441)`（米）
- 某级瓦片坐标：`z=16, x=53973, y=24816`（整数格）

它们指向同一个位置，只是用了不同的**坐标系**和**单位**。
</Callout>

所以学 GIS 的第一个思维习惯是：**看到一组坐标数字，先问它在什么坐标系、什么单位里。** 这一章先把"坐标系"和"单位"这两件事讲清楚。

## 2. 平面直角坐标：最熟悉的"平地"

你在数学课上画过函数图像：一个原点、一条横轴（x）、一条纵轴（y），平面上任何一点写成 `(x, y)`。这叫**笛卡尔平面直角坐标**（Cartesian，/kɑːrˈtiːʒən/，「卡-提-让」），由三件事确定：

- 一个**原点** `O`；
- 两条**互相垂直的数轴**；
- 每条轴的**单位**和**正方向**。

<Callout type="example" title="生活类比：教室座位">
"第 3 排第 5 座"就是一个平面坐标：**原点**是第 1 排第 1 座，两条**数轴**是"排"（向前）和"座"（向右），**单位**是一个座位。换一间教室（换原点或方向约定），同样的 `(3, 5)` 指的就是不同的座位，所以报坐标必须先说清"在哪个系里"。
</Callout>

GIS 里的"投影坐标"（UTM（/ˌjuː tiː ˈɛm/，「尤-提-艾姆」）、高斯-克吕格、Web 墨卡托的那些大数字）就是把地球上的点投到这样一张平面上，单位通常是**米**。

### 三种容易混淆的"平面"

同样是 `(x, y)`，不同领域对 x、y 方向的约定完全不同，这是初学者最容易栽的地方：

| 场景 | x 轴 | y 轴 | 备注 |
|---|---|---|---|
| 数学 / 解析几何 | 向右 | 向上 | 象限逆时针 I → IV |
| 屏幕 / Canvas / 图像 | 向右 | **向下** | 原点在左上角 |
| 中国测量坐标 | **向北** | **向东** | 高斯成果表的习惯 |

<Callout type="warn" title="别把投影坐标当成经纬度">
看到 `x=4350000, y=38500000` 这种 7~8 位数，**不要**当成经纬度。那是高斯-克吕格平面坐标，单位是米：x 是北坐标、y 是东坐标（前两位 `38` 是带号）。经纬度永远在 `±90 / ±180` 之间，单位是度。
</Callout>

## 3. 角度：度、分、秒

描述地球上的位置用的是**角度**，不是米。一个圆周 360°，每 1° 分成 60′（分），每 1′ 分成 60″（秒）。传统大地测量成果常用度分秒（DMS，/ˌdiː ɛm ˈɛs/，「迪-艾姆-艾斯」）书写，但程序里一律先换成**十进制度**再算：

```
40°26′46″ = 40 + 26/60 + 46/3600 = 40.446111°
```

反方向换算：`0.446111° × 60 = 26.7667′`，取整得 `26′`，余下 `0.7667′ × 60 ≈ 46″`。

<Callout type="tip" title="DMS 只是书写格式">
度分秒和十进制度是**同一个单位的两种写法**，就像 1.5 小时和 1 小时 30 分。真正需要区分的"两种单位"是**角度与弧度**（下一节）。
</Callout>

## 4. 弧度：三角函数的语言

程序里的三角函数不吃"度"，吃**弧度**（radian，/ˈreɪdiən/，「雷-迪恩」）。弧度用弧长定义：圆心角 θ（theta，/ˈθiːtə/，「西塔」）所对的弧长 `s` 与半径 `r` 之比 `θ = s / r`。整个圆的弧长是 `2πr`，所以：

```
2π rad = 360°
1 rad  = 180/π ≈ 57.29578°
1°     = π/180 ≈ 0.0174533 rad
```

为什么 GIS 里到处是弧度？因为 `sin / cos / tan / atan2` 的参数和返回值都是弧度，投影公式也一样。比如 Web 墨卡托的纵坐标公式：

```
y = R · ln( tan( π/4 + φ/2 ) )
```

里面的 `φ`（phi，/faɪ/，「法伊」，纬度）必须是弧度。如果你把 `30`（度）直接代进去，等于用 30 rad（约 1719°）去算，结果毫无意义。

JavaScript 里的正确写法是**先把度乘 `π/180` 转成弧度**：

```js
const latRad = lat * Math.PI / 180;      // 度 → 弧度
const y = R * Math.log(Math.tan(Math.PI / 4 + latRad / 2));
```

<Callout type="example" title="算一遍：Web 墨卡托的 y 值">
求北纬 30° 的 Web 墨卡托纵坐标（R = 6378137 m）：

1. 度转弧度：`φ = 30 × π/180 ≈ 0.523599 rad`
2. 代入公式：`tan(π/4 + φ/2) = tan(45° + 15°) = tan 60° ≈ 1.73205`
3. 取自然对数：`ln(1.73205) ≈ 0.549306`
4. 乘半径：`y = 6378137 × 0.549306 ≈ 3503550 m`

如果忘了第 1 步、直接把 30 代进去，等于拿 30 rad（约 1719°）去算，结果完全不可用。
</Callout>

<Callout type="warn" title="度/弧度混用是最隐蔽的 bug">
`Math.sin(45)` 不是 `0.707`，那是把 45 当成弧度算的结果（≈ 0.851）。算 45° 的正弦要写 `Math.sin(Math.PI / 4)`。这类错误**不会报错**，只会让结果悄悄错掉。
</Callout>

<Callout type="must" title="必背 · 角度单位换算">
- 1° = 60′ = 3600″；度分秒换十进制度：度 + 分/60 + 秒/3600
- 1 rad = 180/π ≈ 57.2958°；1° = π/180 ≈ 0.0174533 rad
- 进三角函数前，先把度 × π/180 转成弧度
- 度/弧度混用**不报错**，只会悄悄算错
</Callout>

## 5. 经纬度：用角度标出的球面坐标

现在把角度搬到球面上，就得到经纬度：

- **纬度 φ**：某点与赤道面的夹角，从 `-90°`（南极）到 `+90°`（北极）。赤道是 0°。
- **经度 λ**（lambda，/ˈlæmdə/，「兰姆达」）：某点所在子午面与本初子午面（过英国格林尼治）的夹角，`-180°` 到 `+180°`。东经为正、西经为负。

<MapExample lat={39.9042} lng={116.4074} zoom={9} label="天安门：(116.4074°E, 39.9042°N)。可以拖动地图，看右下角经纬度如何随位置变化。" />

<Callout type="warn" title="经纬度不是平面坐标">
经纬度是**球面上的角度**，不是米。不能直接对它做勾股定理、算面积、画圆形缓冲，那样算出来的单位是"平方度"，没有任何物理意义。这是第二章（投影）要解决的问题。
</Callout>

<Callout type="must" title="必背 · 经纬度取值范围">
- 纬度 φ：-90° ~ +90°，南负北正，赤道 0°
- 经度 λ：-180° ~ +180°，西负东正，本初子午线（格林尼治）0°
- 经纬度单位是**度**，不是米；不能直接算距离/面积
</Callout>

## 6. 一度究竟有多长

这是个关键直觉：**同样 1°，在不同方向、不同纬度，对应的地面长度不一样。**

| 方向 | 每 1° 的地面长度 | 说明 |
|---|---|---|
| 纬度（南北方向） | 约 110.57 ~ 111.69 km | 基本恒定，工程上取 111 km |
| 经度（东西方向） | 约 111.32 km × cos φ | 随纬度升高而缩短 |

<Callout type="example" title="为什么经度间距会缩">
纬线是一个个平行的圆，赤道那个圆最大（周长约 4 万 km），越往高纬圆圈越小，到极点缩成一个点。360 条经线都要挤进这些越来越小的圈里，所以 1° 经度的东西距离要乘一个 `cos φ`：

- 赤道（φ=0°）：1° 经度 ≈ 111.3 km
- 北京（φ≈40°）：1° 经度 ≈ 111.3 × cos40° ≈ 85 km
- 北纬 60°：1° 经度 ≈ 55.7 km，只剩一半
</Callout>

所以"北京到上海差 10 个经度"这种说法，必须带上纬度才有长度意义。

<Callout type="must" title="必背 · 1° 有多长">
- 纬度方向：1° ≈ 111 km，全球基本恒定
- 经度方向：1° ≈ 111.32 × cos φ km，随纬度升高缩短
- 北京（φ≈40°）1° 经度 ≈ 85 km；北纬 60° ≈ 55.7 km
- 说"差几度"必须带上纬度，才有长度意义
</Callout>

## 7. 距离与方位：什么时候能用勾股定理

算两点间距离，方法取决于**范围大小**和**你手上是什么坐标**：

- **小范围、且已投影成平面**（比如某城市的 UTM / 高斯坐标）：直接勾股 `√(Δx² + Δy²)` 就够，误差来自投影变形。
- **大范围、或手上只有经纬度**：用球面大圆距离（haversine 公式，/ˈhævərsaɪn/，「哈-沃-赛恩」）：

```
a = sin²(Δφ/2) + cosφ₁·cosφ₂·sin²(Δλ/2)
d = 2R · asin(√a)        R ≈ 6371 km（地球平均半径）
```

<Callout type="warn" title="别在 Web 墨卡托上量距离">
Web 墨卡托（EPSG:3857）在高纬度把距离和面积都放大了，放大倍数是 `1/cos φ`。在北纬 60° 处，图上量出的距离是实际的 2 倍，面积是 4 倍。量距离请回到球面或等距投影上算。
</Callout>

方位角（bearing，/ˈbɛərɪŋ/，「贝尔-瑞英」）从**正北**起算、顺时针 0°~360°；而数学里的 `atan2(Δy, Δx)` 从**正东（x 轴）**起算、逆时针。两者差 90°，换算：

```
bearing = ( 90 − atan2(Δy, Δx) · 180/π + 360 ) mod 360
```

<Callout type="example" title="算一遍：勾股 + 方位角">
A、B 两点为某城市的高斯平面坐标（米），A `(500000, 3400000)`，B `(500400, 3400300)`。B 在 A 的北方向 400 m、东方向 300 m 处：

1. 距离：`√(300² + 400²) = 500 m`（小范围投影坐标直接勾股即可）
2. 数学角：`atan2(400, 300) ≈ 53.13°`（从东轴逆时针）
3. 方位角：`bearing = 90 − 53.13 = 36.87°`（从正北顺时针）

结论：B 在 A 北偏东约 36.9°、距离 500 m 处。
</Callout>

## 8. 常踩的坑：一个速查清单

1. **度 / 弧度混用**：进三角函数前先 `× π/180`。
2. **经纬度顺序**：`[lat, lon]` 和 `[lon, lat]` 混用。`EPSG:4326` 的轴序、GeoJSON（/ˈdʒiːoʊ ˈdʒeɪsən/，「吉欧-杰森」）的坐标顺序、Leaflet 的 `latLng` 恰好互不统一。
3. **把经纬度当平面坐标**：在地理坐标系上直接算面积/缓冲，单位是"平方度"。
4. **在 Web 墨卡托上量距离/面积**：高纬度严重失真。

<Callout type="must" title="必背 · 易混对比">
- 测量坐标：x 向北、y 向东（数学里 x 向右、y 向上）
- 经纬度是**角度**（度），投影坐标是**长度**（米）
- Web 墨卡托量距/量面积放大 1/cos φ（北纬 60° 处距离 ×2、面积 ×4）
- bearing 从正北顺时针起算；atan2 从正东逆时针起算，相差 90°
</Callout>

<Callout type="tip" title="本章回顾">
- 坐标 = 一组数字，必须知道它在**什么坐标系、什么单位**里；
- 平面直角坐标（米）适合做小范围测量，经纬度（角度）用来标球面位置；
- 程序里角度一律转弧度再进三角函数；
- 经纬度 1° 的长度：南北恒定约 111 km，东西乘 `cos φ`。
</Callout>
