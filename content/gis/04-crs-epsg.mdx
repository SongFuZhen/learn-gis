## 🍼 白话版（先看这个）

> 老司机 3 分钟经验之谈。看懂这块，本章就懂了 80%；下面是可以慢慢查的完整版。

**这章解决什么问题**：`EPSG:4326`、`EPSG:3857` 这些数字满天飞，到底是什么？搞懂它，90% 的坐标错乱问题都能自己查出来。

**我的经验一句话**：EPSG 编号就是坐标的「类型标注」。`4326` 单位是**度**（经纬度），`3857` 单位是**米**（Web 墨卡托平面）。混着用就像把 string 当 number 做加法——不报错，但结果离谱。

**三个数先背下来**：

| 编号 | 是什么 | 什么时候见到 |
|---|---|---|
| 4326 | WGS84 经纬度（度） | GPS、GeoJSON、数据交换 |
| 3857 | Web 墨卡托（米） | 网页地图、瓦片 |
| 4490 | CGCS2000 经纬度 | 国内官方数据 |

**我见过的坑（你大概率也会踩）**：

- **轴序写反**：EPSG:4326 官方是「纬度在前」，GeoJSON 和前端库全是「经度在前」。北京的点写成反的，纬度 116 直接超界。
- **在 4326 上算距离**：算出来单位是「度」不是米，而且 1° 经度在赤道约 111 km、在漠河只剩一半。算距离面积，先转投影坐标系（米）再说。
- **以为「米」都是一回事**：3857 的米和 32650（UTM）的米不是同一套米，坐标不能直接拼。

**必记 3 条**：

1. 4326 是度、3857 是米，先分清再动手
2. 轴序别靠猜，查库的约定
3. 算距离/面积，先把坐标转成米

## 本章你会学到

前面讲了经纬度（地理坐标）和投影（把球面铺平）。这一章把两者统一进一个概念——**坐标参考系（CRS，/ˌsiːˌɑːrˈɛs/，「西-阿尔-艾斯」）**，并介绍给每种 CRS 编号的 **EPSG（/ˌiːˌpiːˌɛsˈdʒiː/，「伊-皮-艾斯-吉」）体系**。搞懂它，你才能看懂 `EPSG:4326` / `EPSG:3857` 到底在说什么，并避开轴序、单位、乱换 EPSG 这三个高频坑。

## 1. 两类坐标

| 类型 | 例子 | 单位 | 特点 |
|---|---|---|---|
| 地理坐标系（GCS，/ˌdʒiːˌsiːˈɛs/，「吉-西-艾斯」） | EPSG:4326 | 度 | 直接用经纬度描述球面位置 |
| 投影坐标系（PCS，/ˌpiːˌsiːˈɛs/，「皮-西-艾斯」） | EPSG:3857、EPSG:32650 | 米 | 平面直角坐标，可量长度/面积 |

投影坐标系 = 地理坐标系（基准面）+ 一个投影方法 + 参数（中央经线、原点、假东/假北）。所以「3857 的米」和「32650 的米」不是同一套米。

<Callout type="example" title="例子 · 同一个点，三套坐标">
北京（约 lon 116.391°，lat 39.907°）在三个 CRS 下的坐标数字完全不同（近似值，用于建立量级直觉）：

- EPSG:4326（度）：`(39.907, 116.391)` —— 官方轴序 lat 在前
- EPSG:3857（米）：约 `(12957000, 4850500)`
- EPSG:32650（米）：约 `(448000, 4420000)` —— 东偏从 500,000 起算

数字对不上不代表算错了，先确认是哪套 CRS，再比较坐标。
</Callout>

<Callout type="must" title="必背 · 两类坐标系">
- 地理坐标系（GCS）：单位是**度**，如 EPSG:4326
- 投影坐标系（PCS）：单位是**米**，可量长度/面积，如 EPSG:3857、32650
- PCS = GCS（基准面）+ 投影方法 + 参数（中央经线、原点、假东/假北）
- 不同 PCS 的「米」不是同一套米，坐标不能直接混用
</Callout>

## 2. EPSG 是什么

EPSG 是一套公开的坐标参考系参数数据集，每个 CRS 有一个整数代码：

- `EPSG:4326` — WGS84（/ˌdʌbəljuː dʒiː ˈɛs ˈeɪti fɔːr/，「达布优-吉-艾斯-艾提-弗」）经纬度（度）
- `EPSG:3857` — Web 墨卡托（Mercator，/mərˈkeɪtər/，「默-凯-特」）（米）
- `EPSG:4490` — CGCS2000（/ˌsiː dʒiː siː ˈɛs ˈtuː ˈθaʊzənd/，「西-吉-西-艾斯-图-扫怎德」）经纬度
- `EPSG:32650` — WGS84 / UTM（/ˌjuːˌtiːˈɛm/，「优-提-艾姆」）50N（米）
- `EPSG:4547` — CGCS2000 / 3° 高斯-克吕格 中央经线 114°E（米）

查代码与参数：[epsg.io](https://epsg.io)、[spatialreference.org](https://spatialreference.org)。

<Callout type="must" title="必背 · 高频 EPSG 代码">
- `4326` = WGS84 经纬度（度）
- `3857` = Web 墨卡托（米）
- `4490` = CGCS2000 经纬度
- `326xx` / `327xx` = UTM 北 / 南半球，xx = 带号
- `4547` = CGCS2000 / 3° 带，中央经线 114°E（米）
</Callout>

## 3. 三个高频陷阱

### 陷阱一：轴序

`EPSG:4326` 的官方轴序是 **纬度在前（lat, lon）**，但 GeoJSON（/ˈdʒiːoʊˌdʒeɪsən/，「吉欧-杰森」）/ 大多数前端库用 **经度在前（lon, lat）**。OGC（/ˌoʊˌdʒiːˈsiː/，「欧-吉-西」）为此单独定义了 `CRS:84`（lon, lat）。写代码时不要靠猜，明确转换。

<Callout type="example" title="例子 · 轴序写反会怎样">
北京的经纬度：lon 116.40，lat 39.91。

- EPSG:4326 官方轴序 → `(39.91, 116.40)`
- GeoJSON / 大多数前端库 → `[116.40, 39.91]`

若把 GeoJSON 的 `[116.40, 39.91]` 当成 (lat, lon) 解读：纬度 116.4 超出 ±90，轻则报错，重则被"宽容"地解析到地球另一端。所以每次接手新库，先查它的轴序约定，再明确转换。
</Callout>

### 陷阱二：单位

在 4326 上算距离得到的是「度」，不是米。1° 纬度约 111 km，但 1° 经度在赤道约 111 km、在 60°N 只有约 55.8 km。距离/面积必须投影到合适的 PCS，或用球面/椭球计算（PostGIS（/ˈpoʊstˌdʒɪs/，「剖斯特-吉斯」）`geography`、Turf（/tɜːrf/，「特弗」）的 geodesic（/ˌdʒiːəˈdesɪk/，「吉欧-戴-斯克」）选项）。

<Callout type="example" title="例子 · 1° 经度到底多长">
问：在北京（约 39.9°N），经度相差 1° 的两点实际相距多远？

1. 赤道上 1° 经度 ≈ 111.3 km
2. 纬度 φ 处，1° 经度 ≈ 111.3 × cos(φ) km
3. 代入 39.9°：111.3 × cos(39.9°) ≈ 111.3 × 0.767 ≈ **85.4 km**

同样的 1°，在赤道是 111.3 km，在北京只剩 85.4 km，到 60°N 就只剩约 55.8 km。所以在 4326 上算出的"0.767 度"既不是 0.767 米，也不能当平面距离用，先投影到合适的 PCS，或用 `geography` / geodesic 计算。
</Callout>

### 陷阱三：随便换 EPSG

不同基准面之间的坐标不能直接套用。Beijing 1954 → CGCS2000 需要基准面转换（七参数/格网），只改 SRID（/ˌɛsˌɑːrˈaɪˈdiː/，「艾斯-阿尔-艾-迪」）会把位置平移几十到上百米。

<Callout type="example" title="例子 · 只改 SRID 的代价">
某物流公司把仓库点位数据从 Beijing 1954 迁到 CGCS2000 系统，为了省事直接把坐标系标注改掉，坐标数字一个没动。

结果：所有点位整体平移了几十到上百米，仓库落进了旁边的地块，与规划红线叠加后全部冲突。正确做法是做基准面转换（七参数/格网），让坐标数值真正变化。
</Callout>

<Callout type="must" title="必背 · 三大陷阱">
- `EPSG:4326` 官方轴序 **(lat, lon)**；GeoJSON / 前端库 **(lon, lat)**；`CRS:84` = (lon, lat)
- 4326 上算距离单位是**度**：1° 纬度 ≈ 111 km，1° 经度随纬度缩小（60°N 约 55.8 km）
- 换基准面必须做基准转换（七参数/格网），只改 SRID 平移几十到上百米
</Callout>

## 4. 分带与 UTM / 高斯-克吕格

投影离中央经线越远，变形越大。工程上把地球按经度切带：

- **UTM**：6° 一带，北半球 `EPSG:326xx`（xx = 带号），南半球 `327xx`。
- **高斯-克吕格**：中国常用 3° 带（也可 6° 带），带号写在 EPSG 名称里（如 4547 = 中央经线 114°E）。

<Callout type="must" title="必背 · 分带规则">
- UTM：6° 一带；北半球 `326xx`，南半球 `327xx`，xx = 带号
- 高斯-克吕格：中国常用 3° 带，带号藏在 EPSG 名称里（4547 = 中央经线 114°E）
- 投影离中央经线越远，变形越大
</Callout>

## 5. 工程约定

1. **存储用 4326**（GeoJSON 默认、交换格式通用）。
2. **算距离/面积**：投影到局部 PCS，或直接用 `geography` / geodesic 计算。
3. **显示用 3857**（瓦片地图的标准平面）。
4. 每次读写都显式带上 CRS，不要依赖「默认是 4326」。

<Callout type="must" title="必背 · 工程四约定">
- 存储/交换用 **4326**
- 算距离/面积：局部 PCS 或 `geography` / geodesic
- 显示用 **3857**
- 读写都显式带 CRS，别依赖默认值
</Callout>
